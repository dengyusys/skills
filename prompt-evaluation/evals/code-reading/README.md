# code-reading：代码阅读指导提示词（文件级）

## 测什么

面向零基础的代码讲解提示词，6 个版本在同 6 个案例上的对比。案例含 3 个合成片段（防抖、闭包陷阱、Dockerfile）与 3 个来自 ai-steward-a 的真实文件（write-queue / executor / record-updater，只读摘录，副本固化在 cases/）。

## 第四轮（2026-09-12）：表达卫生标尺 + v7/v8（合并实验）

背景：用户点破 code-reading 的初衷一半是"输出别有 AI 味"，但旧断言（ASCII 制表符、文字墙）从没测过样式。实测 v6 六篇输出合计 **112 处加粗（单篇最高 33）、36 处"——"、16 处斜杠并列、6 处全角箭头**——内容满分、样式重灾。

本起在 defaultAsserts 挂上新断言 `prose_marker_budget.py`（加粗≤8、破折号≤2、正文全角箭头=0、斜杠并列≤2，代码块与行内代码不计），v1-v6 输出走缓存重判：

| 轮次 | v1 | v2 | v3 | v4 | v5 | v6 | **v7** | v8 | **v9** |
|------|----|----|----|----|----|----|----|----|----|
| 第四轮（新标尺） | 0/6 | 1/6 | 0/6 | 0/6 | 0/6 | 0/6 | **6/6** | 4/6 | - |
| 第五轮（v9 上场） | 0/6 | 1/6 | 0/6 | 0/6 | 0/6 | 0/6 | **6/6** | 4/6 | 4/6 |
| 第六轮（v9 修正表格规则） | 0/6 | 1/6 | 0/6 | 0/6 | 0/6 | 0/6 | **6/6** | 4/6 | **6/6** |

v9 两轮的教训：R8 把「表达优先使用表格和列表」软化为「解释性内容用短段落讲」，Dockerfile 案例立刻退化为大段连续文字被断言抓住；R9 改回「结构优先 + 表格列表受版式预算约束」后 6/6。**防文字墙靠结构化优先，防表格墙靠预算上限，两者不能互替。**

后续补充（v9b 极简版与强模型探针，详见 plain-language README「约束量实验」）：极简版 flash 上 4/6→2/6 不稳（丢的正是"顺手小事讲为什么"覆盖的深度细节）；被测换 glm-5.3 后专家版 v7 5/6、v9 3/6、极简 4/6——约束量的收益在强模型上缩小但不消失。台账 13:49/14:03 两轮变体标签错位一格（v10-minimal 排序问题，已改名 v9b 修复），实际成绩以 plain-language README 实验表为准。

**标尺修订（2026-09-12，用户裁定）**：`prose_marker_budget`（加粗≤8、破折号≤2 等绝对预算）从判死降为观察项（eval.yaml 里已注释，可恢复）；ASCII 示意图、事实保全、文字墙保留判死。理由与数据见 plain-language README「标尺修订」小节——绝对预算曾把内容全对的 v1 压到 0/6。新尺下单轮：v5/v6/v7/v9 6/6，v1 5/6，v9c 用户原则版 5/6。

## 关键发现

1. **具体示例胜过抽象规则**：v1（"别用 ─│┌┐"）和 v5/v6（列出可用字符集）能约束画图行为；v3/v4 只写"仅用基础 ASCII"完全无效。
2. **原则式提示词漏细节**：v2/v4 不讲"空 actions 提前 return""两次缓存检查"这类顺手小事。
3. **v6 的三处修复**：画图前先清点组件（防漏画）、禁止照抄输入材料里的 Unicode 画法（材料会"传染"）、"顺手小事必讲一句为什么"。
4. v1 与 v6 差距（8/9 vs 9/9）小于裁判波动幅度，不作铁证；可靠结论是 v6 ≥ v1 ≫ v2/v3/v4。
5. **样式盲区教训**（第四轮）：旧标尺下 v6 满分，但它的输出满是加粗和破折号——"看不懂"被治好了，"读着累"从没被测过。测什么就得到什么，断言要覆盖初衷的全部两面。

## 失败模式分类（首轮）

- Unicode 制表符违规（机械断言抓）：v2/v3/v4 主要死因
- 内容遗漏（裁判抓）：细节不讲
- 结构顺序（裁判抓）：开篇不点题、评价结论后置
