# code-reading：代码阅读指导提示词（文件级）

## 测什么

面向零基础的代码讲解提示词，6 个版本在同 6 个案例上的对比。案例含 3 个合成片段（防抖、闭包陷阱、Dockerfile）与 3 个来自 ai-steward-a 的真实文件（write-queue / executor / record-updater，只读摘录，副本固化在 cases/）。

## 提示词变体

| 文件 | 标签 | 来源 |
|------|------|------|
| prompts/v1.txt | v1 陪读体 | 用户第一版（大白话陪读） |
| prompts/v2.txt | v2 原则式 | 用户第二版（讲解原则清单） |
| prompts/v3.txt | v3 压缩式 | 用户第三版（公文式压缩） |
| prompts/v4.txt | v4 元任务式 | 用户第四版（固定规则 + 动态策略 + 策略自进化） |
| prompts/v5.txt | v5 合并版 | 评测驱动合并：v1 的具体性 + v3 的原则体系 + 准确性规则 |
| prompts/v6.txt | v6 最终版 | v5 + 三处修复（见下），**当前最优** |

## 关键发现

1. **具体示例胜过抽象规则**：v1（"别用 ─│┌┐"）和 v5/v6（列出可用字符集）能约束画图行为；v3/v4 只写"仅用基础 ASCII"完全无效。
2. **原则式提示词漏细节**：v2/v4 不讲"空 actions 提前 return""两次缓存检查"这类顺手小事。
3. **v6 的三处修复**：画图前先清点组件（防漏画）、禁止照抄输入材料里的 Unicode 画法（材料会"传染"）、"顺手小事必讲一句为什么"。
4. v1 与 v6 差距（8/9 vs 9/9）小于裁判波动幅度，不作铁证；可靠结论是 v6 ≥ v1 ≫ v2/v3/v4。

## 失败模式分类（首轮）

- Unicode 制表符违规（机械断言抓）：v2/v3/v4 主要死因
- 内容遗漏（裁判抓）：细节不讲
- 结构顺序（裁判抓）：开篇不点题、评价结论后置
