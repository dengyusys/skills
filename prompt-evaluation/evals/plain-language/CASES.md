## 一、考卷结构

- 一个案例 = 一段文档摘录（输入）+ 2 条裁判断言（这道题的评分标准）。
- 所有案例统一叠加 **5 条机械断言 + 2 条通用裁判断言**（写在 `eval.yaml` 的 defaultAsserts，对所有提示词变体一视同仁）。
- 判分规则：**任何一条断言失败，该案例即失败**。机械断言抓" measurable 的硬指标"，裁判抓"读起来的感受"；两类互相补位。
- 黄金集只增不改：真实使用中发现提示词表现不符预期的新场景，固化成新案例追加，不改旧案例——保证历轮成绩可比。

## 二、断言清单

### 机械断言（机器判：零成本、零摇摆）

| 断言 | 管什么 | 具体口径 |
|------|------|------|
| `marker_density_reduced.py` | 标记密度（相对原文） | 剥掉代码块与行内代码后计数：加粗、破折号"——"、全角箭头"→"，任何一项都不得比原文多；原文三类总量 ≥4 时，改写后必须下降 |

| `no_prose_wall.py` | 文字墙 | 连续超过 6 行非结构化正文即失败（标题/列表/表格/引用/空行重置计数，代码块内不计） |

### 通用裁判断言（LLM 裁判，对所有案例生效）

1. 改写后的文本像有经验的人写给同事看的说明——自创的缩略说法第一次出现就配了大白话解释，句子有主语和动词，读者不用回头重读去猜指代。
2. 没有改出新的 AI 味——不出现"首先/其次/综上所述/值得一提的是"这类骨架词，没有空洞的开场白、过渡句或总结段；对原文内容的概括性承接句不算空洞。

## 三、六个案例

### 案例 01 · 提案卡配方（箭头链 / 斜杠并列 / 状态机电报腔）

- **出处**：design-language.md §3.6 + §3.13
- **靶点**：一句箭头链压缩四块结构；斜杠并列（`取消 ghost / 确认 primary` 那类）；状态机行为全部塞进括号。考"能不能拆成有主语动词的完整句子，且行为一个不丢"。
- **机器咬点（实算）**：加粗 1 / 破折号 0 / 箭头 5（正文，非行内代码），总量 6 → 三类标记必须下降；11 处行内代码，其中 9 个英文 token 必须逐字存活。
- **裁判两问**：① 提案卡四块结构与状态机行为（确认后行变绿、按钮消失、底部显示时间；取消整卡变淡）完整保留，读者顺着句子能想象出卡片长什么样；② 文件列表行的五个列、状态流转（解析中 → 已就绪/失败）、上传区收缩为细条的行为都在。
- **现状**：摇摆带。内容类断言各变体基本能过，常输在丢一两个记号（`.done` 的点号、`animation-delay:`），多轮间互有胜负。

原文（逐字）：

```markdown
### 3.6 提案卡（确认制交互的核心组件）
结构：头部（分类 + mono 日期）→ 字段行（字段名 / old / → / new）→ 操作行（取消 ghost / 确认 primary）→ 底部状态脚。
状态机：`pending → .done`（行变绿 ✓、按钮移除、脚"已安全写入 ✓ 时间"）/ `.cancelled`（整卡降透明度）。字段行错峰入场 `animation-delay: i*70ms`。（来源：`interfaces/ai-steward-mobile` `.card-proposal`）

### 3.13 文件列表行（状态机）
`名称(ellipsis)/大小/状态/时间/删除(hover 显示)`；状态三点式：`解析中`（琥珀 + 呼吸点）→ `已就绪`/`失败`，落定时 toast；上传区有文件后**收缩为细条**（渐进披露）。（来源：`ai-hub` `.f-row`）
```

### 案例 02 · 布局编排（自创黑话群）

- **出处**：design-language.md §4.5
- **靶点**："错峰编排""让位者""反向镜像"三个自创词连发，全部不解释；破折号插入语连环。考"黑话首现就地配大白话，时序数字不丢不反"。
- **机器咬点**：加粗 3 / 破折号 2 / 箭头 2，总量 7 → 必须下降；行内代码 2 处（`collapse-wrap`、`display`）须存活。
- **裁判两问**：① "错峰""让位者""反向镜像"首次出现就配了大白话解释（如"一个先动完、另一个再动"），没读过原文的人也能懂；② 280ms / 240ms / 约 520ms 完整保留，"正向先收后长、反向先收后展"的镜像关系没写反，三条规则一条不丢。
- **现状**：全变体基本都能过（区分度低，但是底线题）——它在 R1 就把朴素指令 v1 也放行过，之后各轮几乎全绿。

原文（逐字）：

```markdown
### 4.5 布局编排（多段高度变化必须错峰）

凡一个状态切换引发**多段高度变化**（如：终端块收起 + 表单折叠 + 卡片生长），必须错峰编排——同时进行时，上方元素长高会把正在收缩的下方元素往下推，两个位移互相打架（"僵硬感"的来源）：

- **正向**：让位者先收（280ms）→ 240ms 后新内容生长；滚动定位延迟到全部稳定后（~520ms）；
- **反向镜像**：新内容先收 → 240ms 后让位者展开——正反向同一节奏，不要只编排一边；
- 高度显隐一律 `collapse-wrap`（4.1 的例外辩护），`display` 切换会把整块高度瞬插/瞬删（"入场动画不动画布局"）。
```

### 案例 04 · 性能速记（无主语电报句 / 速记黑话 / 缩写）

- **出处**：animation-methodology.md §2 末行 + §5 全节
- **靶点**："墙钟推进""漂移""辩护例外"速记词；无主语电报句；VT / rAF 缩写无解释。考"每条规则独立可读、双信号判定逻辑不被改歪"。
- **机器咬点**：加粗 4 / 破折号 3，总量 7 → 必须下降；6 处行内代码（`transform`、`performance.now()`、`ready`、`finished` 等）存活。
- **裁判两问**：① 每条规则改写后独立可读——"墙钟推进"说清是什么（按真实时间推进而非固定步数）和为什么（后台定时器被节流）；"漂移""辩护例外"要么换直白说法要么就地解释；② "ready 拒绝、或 finished 先于 ready 落定即判不可用"的双信号逻辑没被改歪，8.3ms、1 次/秒等数字完整保留。
- **现状**：中等。加"缩写规则"后（R3 起）规则版变体稳定通过；极简版在此题暴露过 VT 不解释。

原文（逐字）：

```markdown
**通用机制以类为单位复用，不复制声明**——自写副本会漂移（记忆面板冻结事故）。

## 5. 性能与鲁棒

- 只动 `transform`/`opacity`（合成器）；**grid-rows 是唯一辩护例外**（高度显隐无替代方案，实测 8.3ms 帧间隔中位数）。
- 打字机/流式：墙钟推进（`performance.now()`），绝不固定步进——后台定时器被节流到 1 次/秒，固定步进会拖死。
- VT 可用性运行时探测：`ready` 拒绝 **或 `finished` 先于 `ready` 落定**（某些环境 ready 永不落定）= 不可用，学习一次后续直接走降级。
- 遮挡标签页里主线程过渡全部冻结、rAF 停摆——**布局动画必须在面板可见时验证**。
```

### 案例 05 · Apple 三原则表（表格单元格过载 / 术语无解释 / 记号保全）——最硬的骨头

- **出处**：design-language.md §6
- **靶点**：一格塞 3-4 件事的速查表；Clarity/Deference/Depth 只有括号直译没人话；表格 + 链接 + 代码记号最密集。考"表格仍是表格但格子减载、术语配人话、记号一个不丢"。
- **机器咬点**：加粗 2 / 破折号 2，总量 4 → 必须下降；7 处行内代码 + 1 条链接，**18 个 token 必须存活**（`--ease-spring: cubic-bezier(0.34, 1.3, 0.64, 1)` 一条就拆出多个）；版式断言咬表格格 ≤45 字与占比 ≤50%。
- **裁判两问**：① 表格保留为表格或同等速查结构，但每格只说一件事，术语各配一句人话解释；② "阴影只属于浮层、内容卡片保持平面"这条对比原则仍然直白醒目，两组阴影数值的用途（接触影、环境影）说得清。
- **现状**：**至今未破**——建卷以来所有轮次、所有提示词变体（含朴素指令、极简版、合一版、强模型）在这题上全军覆没。模型系统性不肯给表格瘦身——格内仍塞多件事、占比顶到 50-73%。已试过：文字版分层规则、预算数字、拆法示例，均不够。下一步方向：给一张完整的"胖表 → 概览表 + 细节下移"改前改后整表示例。

原文（逐字）：

```markdown
## 6. 产品级美感 · Apple 三原则的落地

> 依据 [Apple HIG 设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles)：**Clarity（清晰）/ Deference（顺应内容）/ Depth（层次）**。目标是"从里到外"的一致质感——每个状态都被设计过，每个表面都有物质感。

| 原则 | 本库落地 |
|------|------|
| Clarity | 侧栏 macOS 式选中指示条（3px 圆角 accent 条）；衬线标题统一 `-0.3px` 光学字距；等宽 + tabular-nums 数据 |
| Deference | 顶部主色 5% 环境光（`body::before` radial，fixed 不拦截事件），页面不是死平的底；**阴影只属于浮层**（命令面板/toast 双层阴影），内容卡片保持 hairline 平面不漂浮 |
| Depth | 阴影双层化：`0 1px 2px`（接触影）+ `0 16px 40px`（环境影），表面"浮"而非"贴"；主按钮 `inset 0 1px 0` 受光高光 + 主色接触影；按压 `scale(0.96)` + 弹簧回弹 |
| 物理感 | `--ease-spring: cubic-bezier(0.34, 1.3, 0.64, 1)` 轻过冲弹簧——只给"有质量"的动效用（按压、toast 入场），位移动效仍用 ease-out-expo（弹簧不滥用） |
```

### 案例 06 · 简笔画标注（名词堆叠 / 中英夹杂 / 电报式禁令）

- **出处**：design-language.md §3.18
- **靶点**："无外圆、放射线角度不均且每根微弯（C 曲线）、长短不一"这类名词串（没有动词，想象不出画面）；"忌等分角度与直线"禁令腔；feTurbulence 等术语裸奔。考"四个手法改完能想象出画面，禁令与限量保留"。
- **机器咬点**：加粗 6 / 破折号 1，总量 7 → 必须下降（本考卷加粗最多的案例）；2 处行内代码 + 1 条链接，3 个 token 存活。
- **裁判两问**：① 四个手法各自能让人想象出画面（星芒 = 放射线角度不等、每根微弯、长短不一、中心一点；圈重点 = 手绘开口椭圆包住关键词；歪箭头配微旋转 mono 手写注；波浪下划线衬在品牌语下），"忌等分角度与直线"这类禁令保留且语气明确；② "简笔画说旁白与重点，UI 说功能"的分工、"一处视图最多 2-3 个标注"的限量、纸感颗粒打底完整保留。
- **现状**：规则版变体（v2-v7）多数通过；朴素指令和极简版挂（画面感与术语解释正是缺了示例与规则后先丢的东西）。

原文（逐字）：

```markdown
### 3.18 简笔画标注系统（营销页 · Claude/Anthropic 风）
比"插画"更轻的一层：**涂鸦式标注**。四个签名手法——
1. **Off-kilter 星芒**（Claude logo 同源）：无外圆、放射线角度不均且每根微弯（C 曲线）、长短不一，中心一个点；忌等分角度与直线

4. **波浪下划线**：Q/T 曲线连缀，衬在品牌语下
纸感颗粒（feTurbulence 5%）打底。原则：**简笔画说旁白与重点，UI 说功能**；一处视图最多 2-3 个标注，多则闹。（来源：`ai-steward-site`；[Claude logo 分析](https://designrush.com/best-designs/logo/claude-logo-design-the-ai-mark-built-to-look-none-of-its-rivals)）
```

## 三·补 · R16 新增两题（现行判分格式，材料与全文详见 CASES-PORTABLE.md）

### 第 7 题 · 闭包、异步回调与变量变化（用户提供）

- **出处**：用户提供（2026-09-13），讲解型任务（"我没有 JavaScript 基础，帮我把这段内容讲懂"）。
- **靶点**：三道理解题（第一段为何打印 success——保留对变量本身的访问；第二段为何打印 loading——参数保存的是调用时的值；setTimeout 只是安排稍后执行、注册与调用是两个时间点）+ 三条讲法判定（区分"变量本身 vs 当时的值"、术语必须配人话、不得展开事件循环/宏任务微任务）+ **代码逐字保留（不得插注释）**。
- **首轮成绩**：0/10，统一挂因是所有版本讲代码时都往代码块里插了编号注释——测出"讲解时手痒改代码"的普遍毛病。
- **修法**：提示词加"讲解写在代码外面，不要往代码里插注释或改动代码"。

### 第 8 题 · 克制解释（新题型：不该过度解释，用户提供）

- **出处**：用户提供（2026-09-13）。一行代码 `const name = user?.profile?.name ?? "匿名用户";`，问"是什么意思"，标准是一句话答完。
- **判分**：含义正确（user/profile 不存在或 name 为 null/undefined 时用"匿名用户"）+ **机械判**（正文去空白 ≤120 字；出现编号/列表/加粗/标题/代码块即挂）+ 展开检查（下定义、讲命名、兼容性、与 || 对比、反例展开均挂）。
- **首轮成绩**：0/10——所有版本都把一行代码讲成六百到九百字的小教程；LLM 裁判对"两句话"标准放水（放过 949 字），机械断言才立住（"硬标准必须机器判"第三次应验）。
- **修法**：提示词加"一句话能答完的问题，一句话答完，不要展开成教程"。

## 五、覆盖缺口与已知难点

1. **案例 05 未破**（见上）：表格瘦身是当前最顽固的失败模式。
2. **预算内耗**：把长列表项拆短会顶爆"连续列表 ≤8 项"（实测出现 13 连项），"拆完按小主题分组"的引导存在但模型不执行。
3. **未覆盖的模式**：英文文档、emoji 滥用、代码注释腔、超长文档（多页级）改写、以及"改写后比原文长太多"的膨胀问题（现在只防丢不防胀）。
