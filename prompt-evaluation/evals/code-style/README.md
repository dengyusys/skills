# code-style：code-style 技能测试（三变体）

## 测什么

仓库 `skills/code-style` 技能的有效性。同一任务发给三个"变身"：

| 变体 | 文件 | 回答的问题 |
|------|------|-----------|
| 无技能 | prompts/baseline.txt | 没有技能会差多少？ |
| 仅主文件 | prompts/skill-core.txt | 只给 SKILL.md 主文件（reference 未加载）会怎样？ |
| 主文件+细则 | prompts/skill-full.txt | 完整形态（四个 reference 全部内联） |

六案例覆盖五条核心规则 + 边界：嵌套三元重构、超长配置拆分、补注释、过度抽象陷阱（正确答案是**不抽**）、合规代码审查（ai-steward-a 的 write-queue.ts，正确答案是**克制**）、JSON 注释陷阱（正确答案是**拒绝写入**）。

## 结果（被测 glm-5.3-flash / 裁判 glm-5.3，2026-09-12）

| 案例 | 无技能 | 仅主文件 | 主文件+细则 |
|------|:---:|:---:|:---:|
| 嵌套三元重构 | ✅ | ✅ | ❌ |
| 超长配置拆分 | ❌ | ❌ | ✅ |
| 补注释 | ❌ | ✅ | ✅ |
| 过度抽象陷阱 | ✅ | ✅ | ✅ |
| 合规代码审查 | ✅ | ✅ | ✅ |
| JSON 注释陷阱 | ✅ | ✅ | ✅ |
| **合计** | **4/6** | **5/6** | **5/6** |

## 三条结论

1. **技能有真实增量**：无技能必挂的两个案例（配置拆分只做表面重组、注释堆 @param），技能变体能救回。
2. **按需加载细则是刚需**：仅主文件在配置拆分上失败——主文件只有一行要点，模型缺判断材料，拿"防过度抽象"当理由拒绝拆分。SKILL.md 的 Reference 使用条件设计被验证有效。
3. **细则有过度应用风险**：完整版把两档运费（>99 免费 / >49 收 5 元）做成 `SHIPPING_TIERS` 注册表 + find 查找，违反细则中"两三个简单分支不注册表化"的反向约束。
