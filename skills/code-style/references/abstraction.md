# 避免过度抽象

对应 SKILL.md「5. 避免过度抽象」。

## 规则

- 公共包只保留多个消费方已经共享，或属于明确稳定边界的部分（常量、契约、动作名）。
- 单侧使用的状态码、错误处理、类型守卫等实现细节留在所在模块，不要塞进公共包。
- 抽取共享模块前先确认消费方和变化方向。只有一个消费方且没有明确边界价值时，通常不算“共享”。
- 边界尚不稳定时，允许暂时保留少量重复，等共同模式明确后再抽取。

## 判断步骤

1. 判断内容是否会被多个消费方使用。
2. 判断它是否属于跨进程、跨包、协议或公共 API 等稳定边界。
3. 既无实际复用也无边界价值时，留在原模块。
4. 抽取后保持“共享面”最小，只暴露消费方真正需要的部分。
