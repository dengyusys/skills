# 注释

> 本文中的原则与约束属于规范；代码仅用于说明。标识符、目录名、配置键和示例数值应结合当前项目调整，除非正文明确标注为固定要求。

对应 SKILL.md「1. 注释」。

## 规范

### 基本要求

- 优先遵循仓库已有的注释语言；没有约定时默认使用中文。不要仅为统一语言批量翻译既有注释。
- 仅在文件或模块职责无法从名称和结构直接判断时，使用适合当前语言的块级注释说明整体职责。
- 无需逐行注释；显而易见的代码不加注释。
- JSON（`package.json` 等）不支持注释，不要写入。

### 常量/数据表注释

需要整体说明的重要常量或数据表（如状态码表、注册表、枚举映射），在变量上方使用当前语言适合的块级或文档注释统一说明；可用箭头 `→` 表示映射关系，或用 `1. 2. 3.` 序号列举各项。不要在每个属性上方重复添加同类注释。

以下为 JavaScript 示例：

```js
/**
 * 环境配置注册表：映射环境名 → 配置。
 *
 * dev  → { apiBase: DEV_API, timeout: 10000 }
 * prod → { apiBase: PROD_API, timeout: 30000 }
 */
```

### 流程注释

流程类说明用箭头串起步骤，步骤类说明用序号列举：

```js
/**
 * 应用启动入口：
 *   1. 加载配置（config/index.mjs）；
 *   2. 初始化依赖（lib/bootstrap.mjs）；
 *   3. 启动 HTTP 服务并监听端口。
 */
```

### 为什么注释

- 注释解释“为什么”（安全边界、防漂移、性能、兼容原因），不只复述代码在做什么。
- 为关键函数/导出项标注职责与约定（如“仅内部模块可调用”“缺失输入抛特定错误”）。

### JSDoc

在 JavaScript 或 TypeScript 中，仅为契约、边界、副作用或使用方式无法从名称和类型直接判断的公共导出项使用 JSDoc（`/** */`）。需要时用 `@param`、`@returns` 等标签补充类型系统没有表达的信息；可选参数可用 `[options.xxx]` 表示。不要为每个导出项机械添加重复类型定义的注释。

其他语言遵循其主流文档注释格式和仓库惯例；行内注释只解释局部且不直观的逻辑。
