# 注释

> 本文中的原则与约束属于规范；代码仅用于说明。标识符、目录名、配置键和示例数值应结合当前项目调整，除非正文明确标注为固定要求。

对应 SKILL.md「1. 注释」。

## 规范

### 基本要求

- 一律使用中文注释。
- 文件/模块顶部用块级注释 `/** */` 说明整体职责。
- 无需逐行注释；显而易见的代码不加注释。
- JSON（`package.json` 等）不支持注释，不要写入。

### 常量/数据表注释

重要常量或数据表（如状态码表、注册表、枚举映射）在变量上方统一用一块 `/** */` 说明，内部用箭头 `→` 表示映射关系，或用 `1. 2. 3.` 序号列举各项；**不要**在每个属性上方分别加注释。

```js
/**
 * 环境配置注册表：映射环境名 → 配置。
 *
 * dev  → { apiBase: DEV_API, timeout: 10000 }
 * prod → { apiBase: PROD_API, timeout: 30000 }
 */
```

### 流程注释

流程类说明用箭头串起步骤，步骤类说明用序号列举：

```js
/**
 * 应用启动入口：
 *   1. 加载配置（config/index.mjs）；
 *   2. 初始化依赖（lib/bootstrap.mjs）；
 *   3. 启动 HTTP 服务并监听端口。
 */
```

### 为什么注释

- 注释解释“为什么”（安全边界、防漂移、性能、兼容原因），不只复述代码在做什么。
- 为关键函数/导出项标注职责与约定（如“仅内部模块可调用”“缺失输入抛特定错误”）。

### JSDoc

导出函数/类/常量使用 JSDoc 注释（`/** */`）描述，并可用 `@param`、`@returns` 标注参数类型、默认值与用途，便于 IDE 提示与后续维护；行内 `//` 注释用于解释局部逻辑。默认值用 `[options.xxx]` 表示可选参数。
