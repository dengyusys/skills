# 项目文档管理

## 目标

在不改变既有产品决策、仓库约定和用户授权范围的前提下，创建、更新、评审或组织软件项目文档。

## 任务入口

1. 判断任务类型：建议或规划、审核、创建、更新、代码实施后的配套文档。
2. 读取仓库级规则；若存在文档索引、产品总纲、相关 Spec、架构或决策记录，只读取与当前任务有关的内容。
3. 检查是否已有同主题文档，并确认当前有效来源。
4. 仓库规则、用户要求和当前有效文档发生冲突时，指出冲突并请求确认，不自行选择。
5. 不默认读取完整 reference。

## 按任务执行

### 建议或规划

只输出建议、清单、依赖关系或执行顺序。用户未要求创建文件时，不修改文件。

### 审核

先输出按严重程度排序的问题，并提供文件或章节定位。用户未明确要求实施时，不修改被审核文档。

### 创建

先确认没有重复或重叠文档，再选择对应 asset 作为起点。遵循仓库现有目录、编号和元信息格式；没有既有约定时才使用本 Skill 的默认规范。新文档默认使用 `Draft`，新 ADR 默认使用 `Proposed`。

### 更新

修改当前有效文档，不另建“新版”“最终版”或重复文件。确需替代时，在获得授权后标记 `Superseded`，并建立双向链接。

### 代码实施后的配套文档

只有当代码变更使现有产品、架构、接口、数据、配置、运维或验收说明失效时，才同步更新受影响文档。不要扩大到无关文档。

## 核心约束

- 一个主题只保留一个当前有效来源。
- 既有仓库约定优先于本 Skill 提供的默认目录和命名方式。
- 涉及用户行为、多模块、接口、数据、安全风险或多步骤验收时，优先创建功能 Spec；简单文案、无行为变化的样式调整和直接 Bug 修复通常不需要。
- 未经真实验证，不得标记为 `Completed`；未确认是当前有效方案，不得标记为 `Active` 或 `Accepted`。
- 代码与文档冲突且会影响范围、数据、安全或外部接口时，暂停相关扩展并请求确认。
- 不写入真实密钥、Token、个人敏感数据或完整生产日志。
- 未经明确授权，不删除、归档、重命名或批量重组文档，不安装、发布或修改外部资源。
- 不把未执行的测试或检查描述为已通过。
- 文档内容必须具体、可验证。禁止以下三类反模式：(1) 过于概括的管理式陈述——"功能行为符合 Spec"必须改为可逐条执行的检查步骤，"严格执行非目标"必须给出可执行的动作；(2) 缺少具体值的软约束——"有限次数"必须给出数字，"负责某模块"必须指向文件路径或函数名；(3) 脱离业务的概念列表——每个概念必须说清"包含什么内容"和"与相邻概念的区别"。创建、更新或审核文档时，发现"看起来有道理但不知道怎么做"的描述即视为不通过。

## Reference 使用条件

按任务读取 `references/document-management.md` 的相关章节：

| 任务 | 读取章节 |
| --- | --- |
| 设计文档目录或判断文档类型 | §3–4 |
| 命名、编号或状态流转 | §5–6 |
| 功能 Spec 生命周期或代码配套更新 | §7–8 |
| 文档与代码冲突、替代或归档 | §9–10 |
| AI Agent 文档协作 | §11 |
| 文档评审 | §12 |
| 文档治理、维护节奏或新项目落地 | §14–16 |

只有在用户要求建立、全面审核文档体系，或任务同时跨越多个文档类型时，才读取完整 reference。

## Assets 使用条件

| 资源 | 使用场景 |
| --- | --- |
| `assets/spec-template.md` | 新建功能 Spec |
| `assets/architecture-template.md` | 新建架构文档 |
| `assets/adr-template.md` | 新建技术决策记录 |
| `assets/progress-template.md` | 新建阶段进度文档 |
| `assets/operations-template.md` | 新建运维文档 |

只在创建新文档时使用模板，不用模板覆盖现有文档。替换全部占位内容，并按仓库约定调整元信息。

## Scripts 使用条件

当前没有 `scripts/`，普通文档任务不需要创建或运行脚本。只有出现需要反复、确定性执行的文档校验逻辑，并且脚本已经随 Skill 提供且经过验证时，才使用脚本。

## 完成条件

建议、规划或审核任务以完成用户要求的输出为准，并明确说明未修改文件。

创建或更新任务结束前，检查目标路径、命名、元信息、状态、链接、单一有效来源和敏感信息。功能 Spec 还必须具有明确范围、非目标和可验证验收标准。

最终报告实际创建或修改的文件，并区分已验证、未验证和当前无法验证的内容。
