# 文档结构与类型

对应 SKILL.md「建文档」。

## 目录结构（示意图，仓库已有自己的结构就照它的来）

```
docs/
├── README.md        # 文档索引：列当前有效文档和阅读顺序
├── product/         # 产品文档：定位、用户、范围、路线图
├── architecture/    # 架构文档：模块、接口、数据、部署、安全
├── specs/           # 功能 Spec：一个功能一份
├── decisions/       # 决策记录（ADR）：一个决策一份
├── progress/        # 阶段进度
├── operations/      # 运维文档：配置、部署、备份、故障
└── archive/         # 归档
```

小项目不用硬凑齐：product.md + architecture.md + specs/ + progress.md 起步，长胖了再拆。

## 文档类型总表

| 类型 | 放哪 | 活多久 | 主要内容 |
|------|------|--------|----------|
| 项目入口 | 根目录、docs/README.md | 长期维护 | 项目介绍、文档索引、阅读顺序 |
| 产品文档 | docs/product/ | 长期维护 | 定位、用户、范围、优先级、路线图 |
| 架构文档 | docs/architecture/ | 长期维护 | 模块、接口、数据、部署、安全边界 |
| 功能 Spec | docs/specs/ | 功能全生命周期 | 单项功能的需求、方案、任务、验收 |
| 决策记录 | docs/decisions/ | 永久保留 | 重要选择、替代方案、收益与代价 |
| 阶段进度 | docs/progress/ | 阶段内维护 | 已完成、进行中、下一步、阻塞项 |
| 运维文档 | docs/operations/ | 长期维护 | 配置、部署、监控、备份、恢复 |
| 归档文档 | docs/archive/ | 只读保留 | 已被替代但仍有历史价值的内容 |

## 根目录四件套（按需）

README.md（项目介绍和常用命令）；AGENTS.md（AI 工具的仓库规则，可选）；CONTRIBUTING.md（协作规范，可选）；CHANGELOG.md（对外的版本变化，可选）。

## 运维文档该写哪六样

有部署或长期运行需求时至少覆盖：环境变量和配置来源；部署、升级和回滚；数据备份与恢复；日志和监控入口；常见故障及安全处理；密钥管理原则（写原则，不写真实密钥）。

## 建文档的时机

- 不预建空文件；
- 需求真出现了才建；
- 同一主题已有文档就更新它，别重复建；
- 研究性内容形成结论了才转正。

## Spec 的粒度

一个 Spec 管一个能独立开发和验收的功能。
例：用户登录、文件上传、数据迁移，各一个 Spec；"做完整个系统"不拆成 Spec，纯样式调整不配 Spec。

## 决策记录（ADR）

什么时候写：选框架、定模块划分、增删关键依赖、改数据模型/部署/安全边界、多方案取舍。
ADR 永不删除，被替代就标 `Superseded` 链到新决策。

## 架构文档

只写"当前算数"的方案。被换掉的方案去 ADR 或 Git 历史里找，别在正文里摆两套打架的方案。

## 进度文档

只记四样：已完成、进行中、下一步、阻塞项。不是流水账。
